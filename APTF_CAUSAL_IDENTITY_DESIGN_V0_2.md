# APTF Causal Identity Design V0.2

Status: DESIGN / DIAGNOSTIC. NOT FROZEN IMPLEMENTATION AUTHORITY.

## Identity separation

- `observation_id`: deterministic identity of one normalized market observation.
- `event_id`: deterministic identity of one logical source/derived event.
- `execution_id`: unique UUIDv4 for one actual runtime processing occurrence.
- `parent_event_id`: deterministic logical event ID of the immediate parent.

Retries/re-executions retain observation/event/parent IDs but receive new execution IDs and telemetry.

## Source stream and sequence

`source_stream_id` is required because `sequence_number` is scoped to `(source_stream_id, instrument_id)`.

For this source:

```text
source_stream_id = aptf:source:v1:FirstRateData:SPY_1min_firstratedata:normalized_v0_1:sha256:73957227a0cc09103f7ca5ff62b011edd7c80c220017d91fb97c5fb5e6a1055d
```

`sequence_number` is the APTF Source-Gateway ordering sequence assigned after normalization, zero-based and monotonically increasing in normalized `event_timestamp_utc` order. Descendants inherit it unchanged. It is not a provider, CSV, broker, database, or Event Hubs sequence.

For the target, normalized-order ordinal is `16`. `source_row_number=17` proves raw-source lineage but is not silently redefined as sequence. The gateway maps normalized ordinal 16 to APTF sequence 16 and records source row 17 only inside payload/source metadata.

## Canonical payload serialization: APTF-CJSON-V1

Normalize recursively:

1. Pydantic models -> `model_dump(mode="json")`.
2. Dataclasses -> ordered field-name mapping.
3. Enums -> `.value`.
4. Tuples -> JSON arrays; lists preserve order.
5. Dictionaries -> string keys sorted by Unicode code point; duplicate/non-string keys rejected.
6. `None` -> JSON `null`; booleans/integers unchanged.
7. Finite Python floats -> JSON number using Python 3.13 shortest round-trip representation; normalize negative zero to `0.0`; NaN/Infinity rejected.
8. UTF-8, `ensure_ascii=false`, separators `,` and `:`, no insignificant whitespace.

This repository-specific canonical profile is versioned. Payload semantics are not changed to hash them.

## payload_sha256 recipe

```text
payload_sha256 = lowercase_hex(SHA256(UTF8(APTF-CJSON-V1(normalized semantic payload))))
```

It excludes the envelope, execution ID, processing timestamps/counters/duration, flags, runtime metadata, and Azure metadata.

D01 payload is one semantic aggregate object with exactly `dmo` and `fmo` members containing real outputs. E2-E5 payloads are the exact ReturnShape, EnvelopeEvaluation, DecisionRecord, and PositionTransitionPlan serializations.

## observation_id recipe

Exact ordered identity array:

```json
[
  "APTF_OBSERVATION_IDENTITY",
  "v1",
  "<source_stream_id>",
  "<instrument_id>",
  16,
  "2022-09-30T08:16:00Z",
  "PROVIDER_EVENT",
  "NormalizedObservationSourceRecord",
  "v0_1",
  "<payload_sha256>"
]
```

General formula:

```text
observation_id = "aptf:obs:v1:sha256:" +
  lowercase_hex(SHA256(UTF8(APTF-CJSON-V1(ordered_array))))
```

The sequence and source stream distinguish distinct source observations even with identical OHLCV/time. Processing values and transport metadata are excluded. Replay of the same normalized observation yields the same ID.

## event_id recipe

Current primary stage cardinality is exactly one logical envelope event per stage: E0 source record, E1 DMO/FMO aggregate, E2 ReturnShape, E3 EnvelopeEvaluation, E4 DecisionRecord, E5 PositionTransitionPlan. A general ordinal remains explicit for future multi-output stages.

Exact ordered identity array:

```json
[
  "APTF_LOGICAL_EVENT_IDENTITY",
  "v1",
  "<observation_id>",
  "<parent_event_id-or-null>",
  "<producer_component>",
  "<producer_version>",
  0,
  "<SUCCESS-or-ERROR>",
  "<payload_type>",
  "<payload_version>",
  "<payload_sha256-or-null>",
  "<stable_error_type-or-null>",
  "<stable_error_code-or-null>"
]
```

```text
event_id = "aptf:evt:v1:sha256:" + SHA256(APTF-CJSON-V1(array))
```

Execution/timing/runtime/flags/Azure metadata are excluded. Error messages are excluded; stable type/code define logical error identity.

## execution_id recipe

Generated by `uuid.uuid4()` at each source/stage processing occurrence; canonical lowercase hyphenated UUID text. It is not derived from market/event/payload facts and affects no other ID/hash.

`runtime_instance_id` and `clock_domain_id` are likewise UUIDv4 identities created once per runtime process lifecycle and monotonic clock domain.

## Existing scientific IDs

D01 trace/state/config hashes, D02 identity, D04 candidate ID, D03 decision/fingerprints, and controller transition/D03 IDs retain frozen meanings. Envelope `scientific_ids` copies them only for indexing.

## Identity invariants

- observation ID assigned once at E0 and inherited E1-E5;
- each logical E0-E5 ID deterministic and distinct by producer/payload/parent;
- every execution ID unique per occurrence;
- E0 parent null; E1-E5 parent previous logical ID;
- child and parent share source stream, sequence, instrument, event time, role, and observation ID;
- no telemetry field enters observation/event/payload hashes.
