# APTF Runtime Core Architecture V0.1

Version: **APTF Runtime Core V0.1**

## Canonical flow

```text
Observation
    -> Validation
    -> Rolling Context / persistent Emitter state
    -> Adaptive Emitter
    -> Immutable Emission (BUY / SELL / HOLD when actionable)
    -> Position State Operator (FLAT / LONG)
    -> Execution Intent (BUY / SELL / NONE)
    -> future Execution Adapter boundary
```

## Components

### Observation

An immutable, source-derived value carrying entity/source identity, physical and source row identity, local/UTC timestamps, OHLCV strings, session, data-valid flag, and quality flags. Required values are never fabricated. Admission maps valid source values to the frozen D01 `NormalizedObservation` without importing a diagnostic runner.

### Validation

Validation executes before D01/D02/D04 mathematics. Missing fields, invalid timestamps/numerics, non-finite OHLCV, false `data_valid`, or non-increasing source time stop that observation. `data_integrity` is not a D04 factor.

### Rolling Context

`RollingContext` retains exactly the 15 most recent completed scientific records. The current observation is evaluated against a snapshot of O_(n-15)...O_(n-1), then committed once after emission construction. There are no block or session resets.

### Emitter State

`EmitterState` exposes completed count, previous BUY/SELL/HOLD decision, and the frozen Emitter's legacy internal-controller feedback state. That legacy state is retained for Test 006A equivalence only and is not production Position State or Execution Intent. D01 recursive state and the context are also persistent runtime state.

### Adaptive Emitter

The Emitter reuses frozen D01, D02, and direct four-factor capturability. Adaptive values are calculated from the prior 15 completed records. Predicates are frozen. No full envelope hysteresis, D03, broker, execution, or P&L layer is invoked.

### Immutable Emission

The emitted scientific record contains observation/context identity, state before/after, D01/D02/four-factor mathematics, adaptive properties, BUY/SELL/HOLD decision, rule path, feedback, source timing, processing timing, and implementation/config fingerprints where applicable. The production value object is frozen and exposes a defensive serialized copy.

### Position Decision

An actionable Emitter decision is exactly BUY, SELL, or HOLD. INITIALIZING is a runtime status, not a terminal Position Decision.

### Position State and operator

Production Position State is exactly FLAT or LONG. A pure six-case operator accepts state-before and Emitter decision and returns immutable state-before, decision, state-after, structural meaning, and Execution Intent.

### Position Transition and Execution Intent

Execution Intent is broker-neutral BUY, SELL, or NONE. Only FLAT->LONG creates BUY and LONG->FLAT creates SELL. Unchanged state creates NONE. Raw decisions never bypass the operator.

### Feedback

Feedback generated by completed actionable emission n updates EmitterState for n+1 or later. It cannot change emission n. Position State is updated separately after the Emitter result.

### Time

Source timestamp and source delta describe market-source sequence. `perf_counter_ns` lifecycle timing describes local processing. Neither is inferred from the other. Execution-specific timing is telemetry and does not alter mathematical equivalence.

### Persistence

Persist between observations: rolling context, D01 recursive state, EmitterState, prior feedback, PositionState, last source timestamp, and sequence identity. Transient: context snapshot copies, local D01/D02/D04 results, timing starts, and validation temporaries. V0.1 defines no database.

### Real-time and asynchronous boundary

The core accepts one observation and requires no future length or dataframe. An asynchronous outer gateway may await observations and call one isolated runtime instance sequentially. It must not concurrently mutate one symbol/channel instance. Separate instances provide isolated state for different channels without speculative cross-symbol logic.

### Future Execution Adapter

The boundary ends at ExecutionIntent. Test 008 may consume that intent and define simulated execution externally. No broker, fill, execution-price, quantity, capital, or P&L API exists in V0.1.
